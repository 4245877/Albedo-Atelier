# Проверка управления печатью — 4 ноября 2026

Проверен путь «загрузка → анализ → подготовка → очередь → запуск → завершение →
снятие модели», обмен данными между разделами и вкладками браузера, ручные
операции, окно запуска и обновление состояния при медленном API.

Уже существовавшие изменения рабочей копии сохранены. Исправления проверяются
вместе с ними. Работающая ферма использовалась только для диагностики через
GET API; запуска печатей, подтверждения физических операций и перезапуска
production в рамках проверки не было.

| Дефект | Причина и исправление |
|---|---|
| Удалённый файл остаётся в «Новой печати» | Раздел ждал своего 20-секундного опроса. Успешные мутации теперь немедленно уведомляют связанные разделы и другие вкладки через BroadcastChannel. DELETE сразу убирает файл и сохранённый выбор; обновление остальных данных идёт отдельно. Учтены каскадное удаление и ответ 404 «уже удалён». |
| После подтверждения стол остаётся заблокированным | Подтверждение ручной операции и прямое подтверждение стола использовали разную логику. Оба пути теперь проходят через один жизненный цикл и закрывают оставшиеся операции текущего стола. Ручные операции связываются с актуальным циклом при создании. |
| Старые снятия моделей блокируют новую печать | Подтверждение актуального стола снимает запросы снятия моделей из цепочки замещённых циклов. Исторические циклы не получают выдуманного времени очистки; калибровки и другое независимое обслуживание сохраняются. |
| Неудавшееся снятие модели продолжает удерживать стол после успешной повторной попытки | Разрешён явный переход FAILED → COMPLETED при подтверждении человеком. |
| Переподключение повторно объявляет уже очищенный стол занятым | Подтверждение через ручную операцию теперь тоже запоминает завершённый файл, сообщаемый устройством. |
| Операция могла объявить стол свободным во время новой печати | Подтверждение ручной операции теперь использует ту же проверку живой телеметрии, что и прямое подтверждение. Отказ откатывает завершение операции. |
| Карточка отправляет устаревший operationId | Кнопка подтверждает актуальное состояние принтера через `/bed/clear`; сервер сам выбирает текущие операции. |
| Повторный вопрос после явного подтверждения стола | Кнопка «Модель снята — стол свободен» сама является подтверждением. Один запрос, защита от двойного клика и немедленное обновление разделов. |
| Окно запуска показывает ответ для прежнего принтера или прежнего открытия задания | Добавлены отмена вытесненных чтений, номера запросов и проверка идентичности сессии. Запуск недоступен до получения актуальной проверки; после ошибки чтение можно повторить. |
| Медленный слайсинг не обновляет результат | Интервальный опрос каждые 4 секунды вытеснял незавершённые чтения. Следующий цикл теперь планируется после ответа; явное обновление отменяет старое чтение. |
| Отменённая загрузка зависает, очередь загрузок не освобождается | Уже отменённый signal отклоняется до создания XHR. У загрузки есть deadline, обработка timeout и очистка abort-listener. |
| Автоочередь показывает прежнее состояние после медленного переключения | Обновление привязано к успешному ответу API, вместо предположения, что запись завершится за 600 мс. |
| После возврата из кеша истории браузера опрос не возобновляется | Обновление доски и затронутых рабочих разделов возобновляется на `pageshow`; межвкладочный канал переподключается. |
| Карточка показывает «готов», хотя ручная операция блокирует запуск | Из readiness больше не исключаются все операции снятия/обслуживания стола. Для AWAITING_CLEARANCE строка стола и так имеет приоритет; на CLEAR оставшаяся операция показывается как причина удержания. |
| Открытые ранее скрытые разделы создают лишнюю нагрузку | Уведомления обновляют видимые разделы; скрытые перечитываются при открытии. Состояние удалённого файла забывается сразу даже в скрытом мастере. Учитывается скрытый родительский режим и возврат из «Зала» в «Работы». |
| Удаление одной модели сбрасывает задания остальных моделей пакета | Сохраняются принтер, рецепт, нарезки и уже поставленные задания оставшихся моделей. |

С работающей фермы прочитаны состояния столов и открытые ручные операции.
Обнаружены накопленные PART_REMOVAL от прежних циклов. Их нельзя считать
доказательством того, что нынешний стол пуст: исправление снимает такие запросы
при явном подтверждении актуального стола, а не по факту получения `idle`.

Воспроизведение до исправления: браузерный сценарий удаления не дождался
исчезновения файла из «Новой печати» за 1 секунду; пять новых сценариев стола
и три сценария гонок окна запуска завершились ошибкой. После исправления
целевые сценарии проходят. Браузерный тест удаления использует две настоящие
вкладки и задерживает повторное чтение списка на 2 секунды: файл исчезает до
ответа повторного чтения.

Проверки выполняются без реальных устройств: временная SQLite, пустой inventory,
fake-транспорты, mock API и отдельный временный Chrome. Телеметрия `idle` не
подтверждает очистку стола; блокировки активной печати и неподтверждённого
запуска сохраняются. Настройки разрешения автоочереди не менялись.
