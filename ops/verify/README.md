# ops/verify — проверка кандидатного образа до деплоя

Два инструмента, оба ничего не меняют на ферме: не трогают рабочие контейнеры,
не пишут в том `orchestrator-data`, не могут достучаться до принтеров.

## 1. Сквозные сценарии на настоящем образе — `run.sh`

```bash
docker build --target production-orca -t atelier-print-orchestrator:verify apps/print-orchestrator
ops/verify/run.sh atelier-print-orchestrator:verify      # ~12 минут
```

Кандидат (тег `:verify`, никогда не `:latest` — см. `scripts/deploy.sh`)
запускается в docker-сети `--internal` (маршрута в LAN нет — скрипт проверяет
это до старта) с пустым каталогом данных (все миграции с нуля), настоящим
OrcaSlicer из `ORCA_HOST_DIR` (как в `compose.orca.yml`) и двумя симулированными
Creality K2 (`fake-moonraker.mjs`). Журнал команд симулятора — источник истины
о том, что физически дошло до «принтера».

| | Сценарий |
|---|---|
| A | STL → K2 → PETG → нарезка настоящим OrcaSlicer → G-code → запуск; без подтверждений — отказ и ни одного байта на принтер; повтор с тем же ключом — тот же run |
| E | печать завершена → деталь на столе → следующий запуск без «стол свободен» отклонён |
| B | готовый G-code → совместимость (файл для A1 отклонён до передачи) → запуск без нарезки |
| D | история → «Напечатать ещё раз» → новое независимое задание тех же байт, без повторной нарезки; дедупликация по requestId |
| C | две STL → один пакет → по одному заданию на каждый принтер |
| F | потеря связи при отправке: (1) команда исполнена, ответ потерян → run удержан, подтверждён наблюдением, ровно один старт; (2) команда потеряна → run «не подтверждён», ничего не повторяется, оператор отмечает «не началась» |
| K | отмена: ожидающее задание — логически, без команд; идущая печать — только физической остановкой, стол остаётся под деталь |
| G | `AUTO_QUEUE_ENABLED=false`: правило не включается, проход не форсируется, стартов нет |
| J | оркестратор убит `SIGKILL` посреди печати → после старта тот же run переподхвачен, повторной команды нет, завершение записано один раз |
| H | автоочередь включена (только в этом стенде): задание без разрешения не кандидат, разрешённое ждёт с названной причиной, стартов нет |

Отчёты и журналы контейнеров — в `$VERIFY_WORK/out` (путь печатается в конце).
Код возврата 0 — все сценарии прошли.

Ограничения стенда: симулятор говорит только по Moonraker (Bambu MQTT/FTPS и
Creality WS не эмулируются); симулированная печать «завершается» по команде
за секунды.

## 2. Миграции на копии рабочей БД — `migration-check.sh`

```bash
ops/verify/migration-check.sh atelier-print-orchestrator:verify   # ~1 минута
```

Снимает согласованную копию `queue.db` (`VACUUM INTO` с read-only соединения,
том смонтирован только на чтение), поднимает на копии кандидата с
`--network none` (принтеры из БД просто офлайн) и сравнивает БД до и после
первого старта: миграции, автоимпорт каталога, ревалидация утверждённых наборов,
восстановление run. Затем проверяет предел отката: текущий рабочий образ на
мигрированной копии обязан отказаться стартовать (`SchemaTooNewError`).

`inspect-db.cjs` — сводка копии БД только на чтение (целостность, схема,
профили, наборы, задания, run, guard, столы, операции).
